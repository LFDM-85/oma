# 日本語ローカルモデル比較 — 2026-09-26

最も改善が大きかったのは、聞き取りの **Qwen3-ASR 0.6B＋Silero VAD**。
考える部分はQwen3.5 9Bが候補だが、正確な書式指定は未解決。
話す部分はCPUでの応答速度ならKokoroを維持するのが妥当。
Qwen3-TTSは同じ文章の試聴ファイルを用意した。通常のモデル設定は変更していない。

## 英語テストのアプリ設定

`tests/voice/run.py` は英語音声を選ぶだけでなく、アプリの `Response language`
を `English`（`en`）へ切り替え、反映を待ち、会話開始前に設定値を検証する。
終了後は元の設定へ戻す。この切り替えを確認する回帰テストを追加し、
ハーネスの8テストが通った。日本語のコンポーネント比較では明示的に日本語を指定した。

## 聞き取る

同じ日本語の合成音声13本、無音・小さなノイズ各1本を使用。
CPU 4スレッドで実行。Whisper系はint8、beam 5、共通のアプリ名コンテキストを使用。
Qwen3-ASRはfloat32。最終のWhisper系測定は他の推論と重ならないよう順次実行した。

| モデル・設定 | 文字誤り率 | 処理時間の中央値 | 無音・ノイズで文字を出さない |
|---|---:|---:|---:|
| 現行 Whisper Small | 12.4% | 1.14秒 | 2/2 |
| Whisper Large-v3 Turbo | 10.1% | 4.26秒 | 2/2 |
| Kotoba-Whisper v2.0 | 11.4% | 3.63秒 | 2/2 |
| Qwen3-ASR 0.6B、VADなし | 3.3% | 1.40秒 | 0/2 |
| **Qwen3-ASR 0.6B＋Silero VAD** | **3.6%** | **1.57秒** | **2/2** |

誤り率は句読点・空白・幅・大文字小文字を正規化した306文字に対する編集距離。
`OmaText` の表記も正規化している。一方、`一` と `1`、`ノーマルモード` と
`Normal mode` などの表記差も誤りとして数えるため、意味理解の失敗率ではない。
録音者・騒音・実マイク条件を変えた一般的な日本語精度の保証でもない。

Qwen3-ASRは、他の3モデルが「加工ログ」とした「過去ログ」を正しく認識した。
長い入力指示の「句読点」も正しかった。ただし「OmaText」を「オマテクト」、
「二足す二」を別の言葉にする例が残る。VADなしでは無音からコンテキスト文章を
生成したため、その構成は採用候補にしない。VADはWhisperと同じSileroの既定値を使用。

一次資料: [Qwen3-ASR](https://huggingface.co/Qwen/Qwen3-ASR-0.6B-hf)、
[Kotoba-Whisper](https://huggingface.co/kotoba-tech/kotoba-whisper-v2.0-faster)。
Qwen3-ASRは日本語を含む30言語対応だが、今回の追加比較は日本語に限定した。

## 考える・操作を選ぶ

実際のO.M.A.プロファイル・ツール定義・日本語設定を使用。各ケースは履歴なし。
新規文書、厳密な文章入力、ミニ/通常モード、閉じるためのウィンドウ列挙、
別れの言葉の翻訳、計算、終了の8課題を各2回実行した。
ツールは実行せず、最初の応答のツール名・引数または回答を評価した。

| モデル・設定 | 条件を満たした応答 | 通常推論の中央値 | 最初のリクエスト |
|---|---:|---:|---:|
| Qwen3.5 4B、推論off | 12/16 | 0.97秒 | 6.83秒 |
| Qwen3.5 9B、推論off | 13/16 | 2.45秒 | 17.04秒 |
| Qwen3.5 9B、推論low | 14/16 | 4.56秒 | 21.04秒 |
| Gemma 4 E2B、推論off | 6/16 | 0.23秒 | 35.55秒 |

通常推論の中央値は、読み込みを含む最初の1件を除いた15件。
温度は0.2、コンテキスト32,768。出力上限はoffが2,048、lowが4,096トークン。
これは会話全体の成功率や日本語能力全般のベンチマークではない。
例えば「閉じる」は最初の `list_windows` 選択だけを評価しており、実際の閉鎖完了は別検証。

- 4Bはこの条件で「一足す一」に「0」と回答する誤りが2回出た。
- 9B offは計算を改善したが、入力文への余計な改行と、終了ツールを呼ばない例が残った。
- 9B lowでも文章入力は2回とも空の文書作成を選び、指定文を一度に渡す条件を満たさなかった。
  後続ターンで入力する可能性はこの測定では評価していない。返答に中国語が混じる例もあり、
  14/16という数だけで日本語品質の向上を断定できない。
- Gemma E2Bはモード変更を口頭で約束するだけで、ツールを呼ばない例が多かった。

精度優先の次候補は9B low、速度とのバランスなら9B off。ただし全面的な置き換えの
判断には実際の音声・ウィンドウ操作を通した再検証が必要。今回は本番設定を変更していない。

一次資料: [Qwen3.5 9B](https://huggingface.co/Qwen/Qwen3.5-9B)、
[Gemma 4](https://ai.google.dev/gemma/docs/core/model_card_4)。

## 話す

CPU 4スレッド、エフェクトなし、同じ日本語3文章で比較。
Kokoroは `jm_kumo`、Qwen3-TTS 0.6B CustomVoiceは日本語プリセット `Ono_Anna`。
話者が異なるため声質だけをそろえた比較ではない。

| モデル | 挨拶の生成時間 | 文書の文章 | 日付・数字の文章 |
|---|---:|---:|---:|
| Kokoro 82M | 4.26秒 | 1.30秒 | 1.98秒 |
| Qwen3-TTS 0.6B | 8.11秒 | 19.71秒 | 36.05秒 |

Kokoroの最初の挨拶には遅延読み込みを含む。Qwenは表とは別に初期読み込み約9.84秒。
文書の文章の生成時間÷音声の長さはKokoro約0.23、Qwen約2.83。
このQwen Python APIの計測は音声全体が返るまでの時間で、GPU利用やストリーミング
最適化の限界性能を測ったものではない。

Whisper Turboでの読み戻しでは、両モデルとも日付・時刻・金額を復元できた。
Kokoroの「こんにちは」が「今日は」と返る例があったが、音声合成と読み戻し側の
どちらの誤りかは、この結果だけでは断定できない。音声の自然さ・好みは未採点。
人が試聴して決めるための音声を用意した。

- [試聴ページ（ローカルHTML、音声埋め込み）](/home/komagata/.local/share/oma/comparisons/2026-09-26-ja/preview.html)
- [ブラウザの試聴ページ](http://127.0.0.1:8768/preview.html)
- [Qwen3-TTS一次資料](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice)

CPU構成で即応性を保つならKokoroを維持する。Qwen3-TTSは読み方・声の比較候補とし、
低遅延の通常会話向けとしては今回のCPU構成をそのまま採用しない。
