## TTS

Kokoro 82MとQwen3-TTS 0.6Bを日本語・英語各20文章で比較。CPU 8スレッド、各1巡。

|モデル|言語|発声開始 中央値 秒 ↓|P95 秒 ↓|最大 秒 ↓|生成RTF 中央値 ↓|ピークRSS GiB ↓|
|---|---|---:|---:|---:|---:|---:|
|Kokoro 82M|ja|0.737|1.106|1.273|0.202|2.30|
|Kokoro 82M|en|0.825|1.261|1.467|0.209|2.30|
|Qwen3-TTS 0.6B|ja|12.255|15.624|17.538|2.724|5.54|
|Qwen3-TTS 0.6B|en|9.569|15.028|22.459|2.675|5.54|

今回のCPU方式ではKokoroが会話の応答速度に適している。RTFは生成時間÷音声の長さで、1未満なら再生時間より速く生成する。
発声開始はAPIの音声取得時刻と先頭無音からの推定で、実スピーカーの計測ではない。
Kokoroはチャンク取得、Qwenは`generate_custom_voice`で全音声を取得する方式。
QwenのGPU・最適化済みストリーミング性能を否定する結果ではない。

両モデル40/40件の生成と読み返しが完了。全80 WAVのハッシュ、一致する文章ID、有限で非ゼロの信号を確認した。
生成エラー0件、チャンク供給時刻から推定したバッファ不足0秒。ただし音の途切れ・不自然な間・発音の正しさはこれだけで合格にしない。
自然さは**人間の評価待ち**。日本語はKokoro `jm_kumo`とQwen `Ono_Anna`、英語は`am_michael`と`Ryan`で声自体も異なる。

Whisper Turboによる読み返しCER参考値は、Kokoroが日本語14.19%・英語19.12%、Qwenが日本語16.17%・英語17.85%。
数字を漢字・英単語から算用数字に変える表記差が多く、これは発音誤り率でも自然さの点数でもない。
試聴で確認したい例は、日本語10番「一足す一」（Kokoro読み返しで欠落、Qwenでは別語）と15番「改行」（両者で別語）。
認識側の誤りもあり得るため、実際の音声欠落と断定していない。差分を全件保存している。

## 再現と制約

[再実行コマンド](../../../tests/voice/evaluation/STT-TTS.md)。モデル、重みのハッシュ、依存バージョン、入力ハッシュ、生の出力を保存。
調整用と評価用は別。ただし既存の評価用データは以前から繰り返し使用しており、未使用のホールドアウトではない。
速度は今回1巡の測定。`--repeat 3`で順序を回しながら反復できる。
実録音・人の試聴・GPU実行・LLMとの同時実行は今回の結論の範囲外。

QwenのSTTは初回の開発実行でファイル読み込みのlibrosa依存に失敗し、PCM配列を直接渡して修正した。
QwenのTTSはオフライン問い合わせの失敗を、保存済み重みのパス指定で修正した。
さらに以前のgreedy設定では開発用日本語1件が無音になった。公式の標準サンプリングへ戻した別実行では日英とも生成できた。
これらの開発失敗は成功へ書き換えていない。TTSの開発ログを同じディレクトリに保存した。
