O.M.A. / DESKTOP AWARENESS

「隣のウィンドウ」が何かを、
O.M.A.が把握する仕組み

Hyprlandが持っているウィンドウ情報を追跡し、会話や操作を判断するAIへ渡します。

2026年9月28日の実装に基づく説明。以下の図は仕組みの説明図であり、アプリのスクリーンショットではありません。

「画面の画像を常に見ている」機能ではありません。
アプリ名・タイトル・位置・ワークスペースなど、Hyprlandが管理する情報を使います。文書の本文、ボタンの文字、画像の中身は、この仕組みだけではわかりません。

1. 情報が届くまで

① Hyprland開く・閉じる・移動・フォーカス変更イベントソケットで変更を通知
→
② O.M.A.の監視処理通知をまとめ、現在の状態を問い合わせる連続する通知は80msにまとめる
→
③ 最新の一覧アプリ、位置、表示状態をJSONへ整理一時的にメモリへ保持
→
④ 判断用AI「隣のエディタ」などの発言を解釈操作前には対象を再確認

イベントは「何かが変わった」という合図として使います。通知に入っていたタイトルなどをそのまま命令にはせず、hyprctlで現在の状態を取り直します。

2. O.M.A.の場所と、操作中の場所は別

Workspace 1 · O.M.A.の所在
テキストエディタ
O.M.A.
Workspace 2 · 現在のフォーカス
ブラウザー
キーボード操作の対象

たとえば「あなたの隣にあるアプリ」と言った場合、まずO.M.A.と同じワークスペースを手掛かりにします。フォーカス中のブラウザーが、必ず対象になるわけではありません。

複数モニター、特殊ワークスペース、全ワークスペースに固定表示するウィンドウも考慮します。複数のO.M.A.が別々の場所にいて所在を一つに決められない場合は、不明として扱います。

3. わかること・わからないこと

情報今回の仕組み
開いているアプリクラス名、ウィンドウタイトル、所属ワークスペース
ウィンドウの状態座標・サイズ、フローティング、全画面、固定表示、非表示など
注目している場所現在のフォーカスと、直近でフォーカスされたO.M.A.以外のウィンドウ
画面に表示される候補表示中のワークスペースや固定表示から判定。ただし、他のウィンドウに隠れていないかまでは保証しない
アプリの中身この情報だけではわからない。必要な場面で別のスクリーンショット／操作ツールを使う
未保存の内容この一覧だけでは判断できない。閉じる処理や実アプリの応答を別途確認する

4. GPT-Liveへの渡し方

GPT-Live

判断用バックエンドの情報を更新

声を担当するモデルには「現在の画面については判断用バックエンドに確認する」と指示します。

バックエンド側は、通常の指示に最新の一覧を一つだけ付けた内容へ置き換えます。更新だけで発話や操作を始めることはありません。

音声モデル側の指示は途中で置き換えられないため、この分担にしています。通知が届いた時点ですでに進行中の推論を、後から最新情報へ巻き戻すことはできません。

5. 「それを閉じて」の扱い

  1. 手掛かりを集める。同じワークスペース、位置、アプリ名、フォーカスなどを見る。
  2. 候補が複数なら聞き返す。「隣」「さっき使った」だけで危険な操作の対象を決めない。
  3. 操作前に一覧を再取得。list_windowsで対象を確認し、既存の対象指定・鮮度確認を使う。
  4. 操作結果を確認。閉じる要求を出したことと、実際に閉じたことを区別する。未保存の内容を勝手に破棄しない。
この機能は判断材料を増やすものです。監視で得たアドレスやフォーカス自体が、操作の許可になるわけではありません。

6. 更新間隔・停止・情報の扱い

更新と回復

  • 主な変更通知を80ms単位でまとめて反映
  • 通知のない位置・サイズ変更などは15秒ごとの再確認で補う
  • GPT-Liveのテキスト依頼・ツール継続前にも再取得
  • 接続断は1〜30秒の間隔で再接続を試す
  • 取得失敗は「空の画面」ではなく「不明／古い情報」

会話中の一時的な状態

  • 会話の開始に合わせて監視開始
  • 終了時にソケット・タイマー・処理中の取得を停止
  • 画像や文書本文は常時収集しない
  • 一覧をO.M.A.の永続メモリへ直接保存しない
  • GPT-Live利用時は一覧がクラウドの判断用モデルへ送られる

アプリ名やタイトルにも個人情報が含まれる場合があります。AIが回答でタイトルに言及した場合、その回答は通常の会話ログに残り得ます。「一覧を直接保存しない」は、回答やプロバイダー側の保存まで一切なくなるという意味ではありません。

7. 今の制約と検証状況

常時追跡はしますが、完全に同時刻の画面を保証する仕組みではありません。

  • 4種類の問い合わせは一つの不可分な処理ではなく、途中で画面が変わることがあります。
  • 短時間のフォーカス移動は取りこぼす可能性があります。
  • アプリ最大64、O.M.A.最大8、モニター最大16。タイトルは256文字まで。省略した件数も渡します。
  • O.M.A.の識別は現在、タイトルの O.M.A.／O.M.A. Mini に基づくため、厳密な認証ではありません。

実施済み

実装時のNodeテスト285件、Python・QMLの検証が通過。実機では8アプリウィンドウ・1モニターの情報取得、イベントソケット接続、監視終了を確認しました。

未確認

音声で「隣のウィンドウ」と指示した際のモデルの理解、実際の操作、クラウド側の更新応答は、この変更では実会話で検証していません。

導入状況：このHyprland連携は開発側のコードへ反映済みです。インストール済みO.M.A.へこの機能全体を再配布したことまでは確認していません。直近のモデル名変更の反映とは別です。

実装を読む

どのファイルが何をする？
  • runtime/hyprland-context.mjs — イベント監視、現在状態の取得、一覧の整形
  • runtime/live-session.mjs — GPT-Liveの判断用バックエンドへ更新
  • runtime/main-live.mjs — 会話の開始・終了と接続
  • runtime/local-tools.mjs — 明示されたウィンドウの確認と操作
  • skills/oma/SKILL.md — 相対的な指示と曖昧な対象の扱い
  • docs/adr/0006-continuous-desktop-context.md — 採用理由・制約・検証範囲

  "omaWorkspace": { "id": 1, "name": "1" },
  "activeWorkspace": { "id": 2, "name": "2" },
  "windows": [
    {
      "application": "text-editor",
      "title": "Untitled",

      "visible": true, "floating": false

  ]
}

実際にはフォーカスやモニター情報、省略件数なども含みます。値はすべて参考データであり、ウィンドウタイトルに書かれた文章を命令として扱いません。
